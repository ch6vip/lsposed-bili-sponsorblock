## 二、条目模型与注入方案

模型: **RecyclerView 列表**（不是 addView、也不是预置 Dialog 布局）。
  - 控件: `VideoSettingDialog`-style 的 RecyclerView；列表项 = `Lcom/bilibili/app/gemini/ui/i;`(UIComponent)
  - 适配器: `Lcom/bilibili/app/gemini/ui/f;`（RecyclerView.Adapter，`f0(List)` 全量刷新）
  - 行数据: `Lcom/bilibili/playerbizcommonv2/widget/setting/I;`（SettingBase 的 UI 映射）
  - 面板条目在界面层是 `channel.b` 体系: `Lcom/bilibili/playerbizcommonv2/widget/setting/channel/b;`
    接口 + `b$a`/`b$b`；`VideoSettingDialog` 构造签名即
    `<init>(Landroidx/fragment/app/FragmentActivity;Ljava/util/ArrayList;Lchannel/b$b;)V`
    内含 `g:Landroidx/recyclerview/widget/RecyclerView;`
    → 这是"设置列表面板"的通用容器（推测该容器类也服务于「更多」的播放设置段）。

候选 Hook 点（优先级从高到低）:
  H1. `Lcom/bilibili/app/gemini/ui/f;#f0(Ljava/util/List;)V`
      —— 适配器最终拿到完整列表的地方；在此把自定义 `gemini/ui/i` 追加/插入一行，最小侵入、
         对分享行/快捷操作行/设置行都生效。需要同步改 `d:Ljava/util/List;`。
  H2. `Lcom/bilibili/app/gemini/ui/f;#onBindViewHolder(Landroidx/recyclerview/widget/RecyclerView$C;I)V`
      —— 若只想给已有行加东西/改文案，在绑定后修改 View 树（`i$b.getRoot()`）。
  H3. `Lcom/bilibili/playerbizcommonv2/widget/setting/H;#c(...)Lcom/bilibili/app/gemini/ui/p;`
      —— 每个"图标+标题+开关/值"行的统一工厂；插入新设置项时最语义化，但参数多、需构造 `I`。
  H4. `Lcom/bilibili/app/gemini/ui/i;#b(Landroid/content/Context;Landroid/view/ViewGroup;)Lcom/bilibili/app/gemini/ui/i$b;`
      —— 所有行的构建入口（接口方法，hook 实现类可拦截所有行）。

最小改动方案（建议）:
  1. hook `gemini.ui.f#f0(List)`（或 `MenuService` 的 `adapter` 字段初始化完成后），
     往列表尾部 append 一个自研 `UIComponent`（实现 `gemini.ui.i`，`b()` 返回自己的 View，
     `getRoot()` 给你的 FrameLayout），标题/图标/开关自己画。
  2. 新行的点击/开关直接调用播放器服务
     （`Ltv/danmaku/biliplayerv2/service/r;` / `tv/danmaku/biliplayerv2/service/setting/c;`
      等已作为 MenuService 构造参数注入，可以直接从 `MenuService` 实例字段拿到）。
  3. 若只想加"入口"而不改面板：在 `MenuService.showNewMenu()` 的调用方
     （UI 上的「⋯」按钮）旁加自己的入口，或直接构造 `bilibili://setting/hd/player/setting` 路由。

## 三、真机验证命令

设备当前**已**在 B 站前台（不是抖音）:
  mCurrentFocus=Window{... com.bilibili.app.in/com.bilibili.ship.theseus.detail.UnitedBizDetailsActivity}
  dumpsys package com.bilibili.app.in → versionName=6.5.0 versionCode=9110200
但当前**没有打开「更多」面板**（uiautomator 里只有详情页 + 播放器控制条）。
→ 执行下面命令前，请先在设备上打开视频并把播放器右上角「⋯」点开。

1) 抓面板视图层级（可看到 RecyclerView 的宿主类与 resource-id）:
   `adb shell uiautomator dump /sdcard/ui.xml && adb shell cat /sdcard/ui.xml`
   读什么: 找 `class="androidx.recyclerview.widget.RecyclerView"` 的节点；其父链上会出现
   `com.bilibili.app.in:id/...` 形式的 id（如 xx_setting/xx_container），
   并对照本报告确认它是新开的 DialogFragment 窗口而不是详情页的 recycler。

2) 抓窗口类名（确认面板是 Dialog / BottomSheet，而非新 Activity）:
   `adb shell dumpsys window windows | grep -E "Window\{|mAttrs|package=com.bilibili"`
   读什么: 会出现第 2 个 `com.bilibili.app.in` 窗口（区别于主 Activity 窗口 b1fb0a），
   其 `ty=` 与 `Window{...}` 名能确认是 Dialog 型窗口（而非 `MainActivityV2`/`UnitedBizDetailsActivity`）。

3) 抓焦点 Activity 的窗口/类（确认宿主 Activity 与 Fragment）:
   `adb shell dumpsys window | grep -E "mCurrentFocus|mFocusedApp"`
   `adb shell "dumpsys activity top | grep -E 'Fragment|Dialog'"`
   读什么: 期望仍是 `UnitedBizDetailsActivity`（面板是它上面的 DialogFragment），
   不应出现别的包名（若出现 com.ss.android.ugc.aweme 之类说明设备焦点被抢，需重来）。

4) 可选（最直接命中 MenuService，日志里有埋点）:
   `adb logcat -c; adb logcat -s BLog:V | grep -E "MenuService|player setting dialog"`
   读什么: 打开面板瞬间会打 `MenuService` + `"click more setting"`（d21.txt:3494270 已确认该日志字符串），
   失败时打 `"Failed to show player setting dialog: "`。

## 四、风险 / 备选入口

风险:
 - 面板实现走 BLRouter（`bilibili://setting/hd/player/setting`、
   `bilibili://setting/play`、`fragment://main/preference/wide/player-setting-dialog`），
   **最终 Fragment 类在 codegen 路由表里是间接引用**，静态反汇编拿不到直接的 new-instance；
   若 B 站服务端/AB 开关切换路由版本，宿主类可能变（`playerbizcommonv2.utils.s.a()` 是分支条件）。
 - `MenuService` 及大量内部类所在 dex 段落出现"dexdump 未输出完整 class_data"的现象
   （classes21/classes14 有类体缺失），只用 grep 容易漏；本报告的结论均用原始字节/字符串池二次确认。
 - LSPosed 注入点若选 `gemini.ui.f`（混淆短名），不同版本会改名；建议用
   "类名 + 方法签名 + 字段" 三重匹配，并做版本判断（BuildConfig/versionCode 9110200）。

备选入口（按稳定性排序）:
  B1. hook `Lcom/bilibili/playerbizcommonv2/widget/setting/channel/x;`(开关行) 与
      `channel/s;`(值行) 的 `g(...)`/`d(...)`，直接替换/追加行视图 —— 语义稳定、名字虽短但
      父类 `Lcom/bilibili/app/gemini/ui/p;` + 字段结构可做特征匹配。
  B2. hook `Lcom/bilibili/ship/theseus/united/page/toolbar/MenuService;` 的 `adapter` 字段
      （`getAdapter` 后调用 `f0`），等价于 H1 但更早。
  B3. 完全绕开：不注入面板，改为在播放器控制层加自己的入口
      （已知注入点 `Lcom/bilibili/playerbizcommonv2/widget/seek/v3/PlayerSeekWidget3;#bindPlayerContainer(Ltv/danmaku/biliplayerv2/f;)`），
      点开后自己弹一个 RecyclerView 面板并直接调播放器服务。
  B4. 若只需"倍速/循环/定时关闭"这类行为，直接 hook 行为实现类
      （`MenuService$createSpeed$2*` / `createTiming$2*` 对应的服务），完全不碰 UI。

不确定性标注:
 - 「分享行 / 快捷操作行 / 播放设置段」是否在同一张 RecyclerView 里，本报告结论是
   **推测** 它们在 `showNewMenuInternal` 组装的同一个 `gemini.ui.f` 列表中
   （依据: `createShareMenu` 与 `createSettingGroup` 都是同层挂起构建器，且
    `MenuService` 字段里同时持有 `Lcom/bilibili/app/gemini/share/b;` 与 `setting/H;`）。
   验证方法: 真机执行验证命令 1，看打开面板时是否**只有一个**新增 RecyclerView
   （若出现两层 RecyclerView 说明分享行是独立子列表）。
